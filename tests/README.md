# בדיקות

```bash
node tests/run.mjs
```

צריך `playwright` ו-`http-server` מותקנים (גלובלית זה בסדר).

## איך זה עובד

הבדיקות רצות על **קוד האפליקציה האמיתי**, לא על עותק. `harness.mjs` לוקח את
`index.html` כמו שהוא ומוסיף לו [import map](https://developer.mozilla.org/docs/Web/HTML/Element/script/type/importmap)
שמחליף את `core.js`, `shifts.js`, `weather.js` ו-`season.js` בדמה מתוך `stubs/`.
כל השאר — `creative.js`, `launch.js`, `styles.css` — הם המקור.

`stubs/core.js` מחזיק **Firestore מזויף שבאמת עושה הלוך-חזור**: `setDoc` כותב
לחנות בזיכרון ומפעיל את ה-`onSnapshot`, בדיוק כמו פיירסטור אמיתי. ככה נבדק
שהתמונה נשמרת, חוזרת ומצטיירת בלוח. הרשת מזויפת דרך `window.__api`, כך
שאפשר לבדוק גם תשובה תקינה וגם נפילה.

## מה נבדק

| קובץ | מה |
|---|---|
| `ui.mjs` | הלוך-חזור של התמונה, שער ההוספה, מסך הכתיבה, ייצוא, רצועת השבוע, תקציב פיירסטור, מצב כהה, נגישות, נקודת פתיחה אחת |
| `worker.mjs` | שכבת תרגום השגיאות לעברית בוורקר, על הקוד האמיתי |
| `version.mjs` | ש-`APP_VERSION` ב-config.js ו-`VERSION` ב-sw.js זהים |
| `table.mjs` | קריאת CSV/TSV והפרופיל שנשלח לסוכן הניתוח (`table.js`) |

## סימולציה של שבוע שלם

```bash
node tests/sim.mjs
```

לא בדיקה — מדידה. `fullcore.mjs` מייצר מ-`core.js` האמיתי עותק שבו רק Firebase
מוחלף בדמה (`stubs/core-full.js`), ואז **`app.js` וכל המודולים רצים כמו שהם**,
עם מנהל מחובר. הסקריפט עובר את שבוע הבעלים — ימים, אישור, נעילה, שיגור, פוסט,
ייצוא, עובד, יומן — וסופר לכל מסע נגיעות, שדות מוקלדים והחלטות שהאפליקציה
זרקה עליו (חלונות אישור, בחירות). זה מה שמראה איפה האפליקציה מסורבלת.

`photo.jpg` הוא צילום סינתטי (150KB) שנכנס דרך שדה הקובץ האמיתי, כדי שנתיב
ההקטנה ירוץ כמו שהוא רץ אצל הבעלים.

## מה לא נבדק

פיירסטור אמיתי, כללי ההרשאות, ה-Worker בענן, ו-Meta Graph API. את אלה
אפשר לבדוק רק מול המערכת החיה.
